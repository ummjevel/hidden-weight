# Fracture 연속형 바닥·벽 아트 개선 설계

## 목표

3번 맵 Fracture의 일반방 F01~F12와 비밀방 FS1~FS3에서 바닥과 벽이 짧은 장식 블록의 반복으로 보이는 문제를 해결한다. 밝은 백색 석재와 청색 유리로 이루어진 미래 유적의 정체성은 유지하면서, 튜토리얼 지형처럼 각 충돌 구간이 하나의 연속된 구조물로 읽히게 한다.

## 현재 문제

`Fracture_TerrainTiles_v2.png`는 6열 타일 시트로 분할되고, 런타임의 `CameraLockedRoomBackground`가 각 바닥 구간을 짧은 정사각형 모듈로 다시 나눈다. 이 때문에 고대 건축 장식과 유리 문양이 약 1~2유닛 간격으로 반복되고, 각 모듈의 경계에서 형태가 끊긴다. 세로벽 역시 같은 크기의 장식 켜를 연속해서 쌓아 독립된 블록들이 붙어 있는 것처럼 보인다.

튜토리얼은 긴 표면, 긴 세로벽, 반복 가능한 내부 채움재를 역할별로 분리해 사용하므로 동일한 문제가 덜하다.

## 선택한 접근

기존 Fracture 원화를 바탕으로 연속형 전용 모듈을 파생하고, 런타임 배치 규칙을 구간 중심으로 변경한다. 완전히 새로운 이미지 생성은 기본 경로로 사용하지 않는다. 기존 배경과의 색감·붓질 차이를 피하고 현재 원화의 품질을 그대로 활용하기 위해서다.

### 아트 모듈

다음 역할을 분리한 새 버전의 PNG 에셋을 `Assets/Art/Fracture/Environment/Terrain` 아래에 추가한다.

- 긴 수평 표면 중앙 모듈: 현재 시트의 안정적인 중앙 구간을 사용하며 강한 문양의 빈도를 낮춘다.
- 수평 좌우 끝단: 실제 지형이 끊기는 곳에서만 사용한다.
- 긴 세로벽 중앙 모듈: 장식보다 석재·유리 재질이 먼저 읽히는 구간으로 만든다.
- 세로벽 상단·하단 마감: 노출된 벽의 시작과 끝에만 사용한다.
- 내부 채움용 저대비 텍스처: 두꺼운 블록의 면이 비어 보일 때만 배경보다 약간 앞선 명암으로 사용한다.

파생 작업은 결정적으로 재현 가능한 프로젝트 로컬 스크립트로 수행한다. 소스 시트를 덮어쓰지 않고 `v3` 이름의 새 파일을 생성한다. 불필요한 장식은 중앙 모듈에서 제외하고, 이음새 양쪽에 소량의 안전 여백을 둔다.

### 런타임 배치

`TraversalArtPalette`에 Fracture 연속형 모듈 참조를 추가하고, 완전한 세트가 존재할 때만 새 경로를 사용한다. 누락된 경우 기존 `TerrainTileSet` 경로로 안전하게 되돌아간다.

`CameraLockedRoomBackground`는 다음 규칙으로 지형을 입힌다.

- 연속된 수평 타일을 하나의 run으로 취급한다.
- 좌우 끝단은 run당 한 번만 배치한다.
- 중앙 모듈은 원본 종횡비를 유지한 채 긴 구간 단위로 반복한다.
- 마지막 중앙 모듈만 남은 폭에 맞추되 과도한 왜곡이 생기면 모듈 수를 조정한다.
- 인접 모듈은 작은 월드 단위 오버랩을 가져 투명 픽셀이나 샘플링으로 생기는 틈을 숨긴다.
- 세로 노출면도 전체 높이를 하나의 run으로 보고 상단·중앙·하단으로 구성한다.
- 짧은 턱은 장식 기둥으로 보이지 않도록 저대비 벽면 또는 단일 마감 모듈만 사용한다.
- 충돌 Tilemap, BoxCollider2D, 방 크기, 이동 경로는 변경하지 않는다.

독립 발판과 `BuildSolidBlock` 기반 벽도 같은 연속형 모듈 규칙을 사용한다. 이동·붕괴·징조 발판처럼 상태별 전용 스프라이트가 이미 있는 오브젝트는 기존 아트를 유지해 기능 구분을 보존한다.

## 적용 범위

- `Room_Fracture_F01`~`Room_Fracture_F12`
- `Room_Fracture_FS1`~`Room_Fracture_FS3`
- `Zone_Fracture_Full`
- 위 씬을 다시 생성하는 Fracture 빌더 경로

Residue, Gaze, Prologue의 팔레트와 배치 결과는 변경하지 않는다. 배경 이미지, 캐릭터, 적, 문, 상호작용 오브젝트 및 게임플레이 수치는 범위 밖이다.

## 오류 처리와 호환성

- 새 모듈 중 하나라도 누락되면 기존 Fracture 타일셋을 사용한다.
- 스프라이트 크기가 0이거나 잘못 임포트된 경우 해당 run을 건너뛰고 오류를 기록한다.
- 생성 스크립트는 원본 파일 존재 여부와 출력 이미지의 크기·알파 채널을 검사한다.
- 씬을 여러 번 로드하거나 스크립트를 재컴파일해도 런타임 아트 루트가 중복 생성되지 않아야 한다.

## 검증

### 자동 검증

- 새 에셋이 존재하고 Sprite로 올바르게 임포트되는지 검사한다.
- 팔레트가 새 Fracture 모듈을 모두 참조하는지 검사한다.
- 긴 바닥 run에서 생성되는 강한 장식/끝단 개수가 타일 셀 수에 비례해 증가하지 않는지 검사한다.
- 수평 표면의 윗면과 세로벽의 외곽이 실제 Collider 또는 Tilemap 경계와 허용 오차 내에서 일치하는지 검사한다.
- Fracture 15개 방 및 전체 지역 씬 생성이 오류 없이 완료되는지 검사한다.
- 기존 지역 테스트와 플레이 가능성 테스트를 실행해 충돌과 진행이 유지되는지 확인한다.

### 시각 검증

- 스크린샷과 같은 긴 평지에서 장식이 매 칸 반복되지 않고 하나의 긴 구조로 읽혀야 한다.
- 바닥 모듈 사이에 검은 선, 투명 틈, 갑작스러운 문양 절단이 없어야 한다.
- 세로벽이 동일한 블록을 쌓은 기둥처럼 보이지 않아야 한다.
- 플레이어가 밟거나 벽을 잡을 수 있는 면은 배경과 구분되어야 한다.
- 밝은 지형이 캐릭터보다 강하게 튀지 않도록 기존 배경과의 명도 관계를 유지한다.

## 완료 기준

Fracture의 15개 방과 전체 지역 씬에서 바닥·벽이 충돌 구조와 정확히 맞고, 짧은 장식 타일의 반복과 어색한 접합부가 제거된다. 다른 지역의 화면과 Fracture의 게임플레이 동작에는 회귀가 없어야 한다.
