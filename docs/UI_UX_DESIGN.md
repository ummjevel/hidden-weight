# Hidden Weight UI/UX 설계

> 문서 상태: 1차 제작 기준안
> 기준일: 2026-07-28
> 대상 플랫폼: PC 16:9 우선, 키보드·게임패드 동등 지원
> 연결 문서: `GAME_DESIGN.md`, `EMOTION_SYSTEM.md`, `WORLD_MAP.md`, `DESIGN_IMPLEMENTATION_GAP_ANALYSIS.md`

---

## 1. 목표

Hidden Weight의 UI는 정보를 많이 보여주는 계기판이 아니라, **감정을 마주하는 순간에만 조용히 모습을 드러내는 보조 감각**이어야 한다.

플레이어가 UI를 읽느라 세계를 놓치지 않도록 다음 경험을 목표로 한다.

1. 평소 화면은 최대한 비워 환경과 캐릭터를 보게 한다.
2. 위험·입력·진행 조건은 실패 전에 알아볼 수 있다.
3. 감정 능력은 색뿐 아니라 형태·움직임·소리로 구분한다.
4. 길 찾기는 랜드마크가 우선이고 지도는 기억을 보조한다.
5. 파편은 수집 체크리스트보다 해석과 연결의 경험을 만든다.
6. 사망·재도전·저장·메뉴 이동에서 진행 유실에 대한 불안을 만들지 않는다.

### 1.1 UX 성공 기준

- 첫 플레이어가 별도 설명 없이 3분 안에 이동·점프·공격을 수행한다.
- 새 감정 스킬을 얻고 2분 안에 안전한 상황에서 한 번 성공한다.
- 피해 원인을 피격 후 1초 안에 설명할 수 있다.
- 체크포인트 활성화와 저장 완료를 혼동하지 않는다.
- 길을 잃었을 때 30초 안에 랜드마크, 최근 출구 또는 지도로 방향을 회복한다.
- 사망 후 조작 가능한 상태로 돌아오기까지 6초를 넘기지 않는다.
- 키보드와 게임패드에서 모든 메뉴를 마우스 없이 사용할 수 있다.
- 색각 이상 모드에서도 되감기·숨죽이기·예지·자각·위험을 구분한다.

## 2. 현재 UI 진단

### 2.1 구현된 화면과 피드백

| 기능 | 현재 상태 | 문제 |
| --- | --- | --- |
| 타이틀 | 시작, 잔재 개발 진입, 종료 | 이어하기·설정·확인 대화상자 없음, 개발 버튼 노출 |
| HUD | 고정 하트 3개, 스킬명·쿨타임 숫자, 파편·재화 수 | 체력 성장 미표시, 정보 우선순위가 평면적, 텍스트 의존 |
| 되감기 | 화면 우측 게이지 | 대상과 게이지가 멀리 떨어져 시선 이동이 큼 |
| 파편 | 하단 한 줄, 새 파편이 오면 이전 표시 취소 | 연속 획득 시 내용 유실, 다시 읽기 불가 |
| 튜토리얼 | 월드 공간에 `K`, `L` 등 고정 텍스트 | 리맵·패드 대응 불가, 완료 여부·재노출 정책 없음 |
| 일시정지 | 계속하기, 타이틀로 | 지도·기록·설정 없음, 타이틀 이동 시 진행도 즉시 초기화 |
| 페이드 | 씬 전환 암전 | 로딩·저장 상태와 입력 잠금 피드백 없음 |
| 메뉴 기술 | Legacy uGUI Text와 런타임 계층 생성 | 한글 폰트·레이아웃·현지화·에디터 조정·테스트가 어려움 |

### 2.2 유지할 장점

- HUD가 플레이 상태에서만 나타나는 원칙.
- 파편 텍스트가 게임 시간을 멈추지 않는 방식.
- `GameManager`와 UI 사이를 이벤트/프레젠터로 분리한 방향.
- 페이드와 파편 표시가 `unscaledDeltaTime`을 사용해 일시정지 중에도 안전한 점.
- 튜토리얼을 긴 설명창 대신 실제 장소에 배치한 점.

## 3. 정보 구조

```text
타이틀
├─ 이어하기             저장이 있을 때만 활성
├─ 새 게임              기존 저장이 있으면 확인
├─ 설정
│  ├─ 게임플레이
│  ├─ 조작
│  ├─ 오디오
│  ├─ 화면
│  └─ 접근성
├─ 제작진
└─ 종료

플레이
├─ 상시 HUD             체력, 현재 감정, 자각 상태
├─ 상황 HUD             대상, 채널링, 보스, 획득, 저장
├─ 일시정지
│  ├─ 계속하기
│  ├─ 지도
│  ├─ 기억 기록
│  ├─ 조작법
│  ├─ 설정
│  ├─ 체크포인트로 돌아가기
│  └─ 타이틀로
└─ 사망/재시작

엔딩
└─ HUD 제거, 자각 입력 피드백만 세계 안에서 표현
```

### 3.1 정보 우선순위

| 우선순위 | 정보 | 표시 방식 |
| --- | --- | --- |
| 즉시 생존 | 체력 변화, 공격 예고, 피격 방향 | 캐릭터 주변+화면 가장자리, 즉각 |
| 현재 행동 | 감정 대상, 채널링, 쿨타임, 입력 실패 | 대상 주변, 입력 중에만 |
| 공간 진행 | 출구, 체크포인트, 잠긴 길, 보스 | 세계 오브젝트 우선, 필요 시 짧은 안내 |
| 장기 진행 | 파편, 재화, 숏컷, 수집 기록 | 획득 토스트와 일시정지 메뉴 |
| 시스템 | 저장, 연결 해제, 옵션 변경 | 화면 모서리 또는 모달 |

재화·파편 총량은 전투 중 판단에 필요하지 않으므로 상시 HUD에서 제거한다. 획득 직후 2초간 토스트로 보여주고, 전체 수량은 기록 메뉴에서 확인한다.

## 4. 공통 시각 언어

### 4.1 형태

- 패널은 완전한 사각형보다 한쪽이 미세하게 어긋난 얇은 윤곽을 사용한다.
- UI 장식은 세계의 핵심 모티브인 원, 균열, 겹친 윤곽을 사용한다.
- 모서리 장식을 늘리지 않고 정보 그룹당 하나의 상징만 둔다.
- 배경 패널은 불투명 검정이 아니라 먹색 72~84%와 약한 블러를 사용한다.
- 선택 항목은 크기 확대보다 이중 윤곽이 하나로 합쳐지는 애니메이션으로 표현한다.

### 4.2 색

| 용도 | 기본 방향 | 보조 형태 |
| --- | --- | --- |
| 중립 UI | 뼛빛 흰색, 먹색, 저채도 회청 | 단선 원형 |
| 잔재·되감기 | 탁한 앰버·골드 | 반시계 방향 궤적, 역방향 입자 |
| 응시·숨죽이기 | 청록·보라 | 닫히는 눈꺼풀, 수축하는 원 |
| 균열·예지 | 민트·라벤더·옅은 살구 | 앞쪽으로 갈라지는 이중 윤곽 |
| 자각 | 거의 무채색 | 두 겹 윤곽이 정렬되는 형태 |
| 위험 | 주홍·적색 | 톱니/삼각 파형, 짧은 진동 |
| 회복·안전 | 따뜻한 아이보리 | 안정된 원, 느린 호흡 |

색은 의미를 강화할 뿐 단독 신호로 쓰지 않는다. 예를 들어 되감기는 골드 색과 함께 역회전, 예지는 민트색과 함께 앞선 위치의 이중 윤곽을 반드시 사용한다.

### 4.3 타이포그래피

- 한글·영문 전체 글리프를 포함한 TextMeshPro SDF 폰트를 프로젝트에 포함한다.
- 본문은 장식 없는 고가독성 글꼴, 지역명·타이틀만 얇고 길게 뻗은 제목 글꼴을 사용한다.
- 1080p 기준 최소 크기: HUD 24px, 본문 28px, 버튼 30px, 제목 44px.
- 본문 한 줄은 한글 24자를 넘기지 않고, 파편은 최대 두 줄로 자른다.
- 글자에는 1~2px 외곽선 또는 반투명 그림자를 적용해 모든 지역 팔레트에서 읽히게 한다.
- 영문 대문자만으로 된 긴 버튼과 자간 과다 사용을 피한다.

### 4.4 화면 기준

- 기준 해상도: 1920×1080, `Scale With Screen Size`, Match 0.5.
- 안전 영역: 화면 가장자리 5%, 32:9에서는 핵심 HUD를 16:9 내부에 유지.
- 16:10·21:9·32:9에서 배경은 확장하고 메뉴 콘텐츠 폭은 최대 1280px로 제한.
- HUD 요소끼리 최소 16px, 조작 대상 버튼은 최소 56×56px.

## 5. 플레이 HUD

### 5.1 기본 배치

```text
┌──────────────────────────────────────────────────────────┐
│  ◉ ◉ ◌  체력                         감정 문양  [K]      │
│                                      쿨타임 원형         │
│                                                          │
│                                                          │
│                         플레이어                         │
│                    [K 길게 누르기]                       │
│                      ◜──────◝                            │
│                                                          │
│                                                          │
│             “파편의 짧은 문장…”                          │
│  +3 재화                                      저장 ◌     │
└──────────────────────────────────────────────────────────┘
```

### 5.2 체력

- 좌상단에 원형 핵 1개를 최대 체력 수만큼 표시한다.
- 가득 찬 체력은 안정된 원, 빈 체력은 금이 간 외곽선으로 남겨 최대치와 현재치를 동시에 보여준다.
- 최대 체력은 런타임에 동적으로 생성하며 고정 3개 배열을 사용하지 않는다.
- 피해 시 해당 칸이 중심에서 바깥으로 120ms 갈라지고 180ms 안에 빈 윤곽이 된다.
- 회복 시 빈 윤곽이 안쪽으로 채워지며 250ms 동안 한 번 호흡한다.
- 체력 1일 때만 전체 체력 그룹이 1.2초 주기로 미세하게 수축하고 저주파 심장음을 낸다.
- 무적 시간은 하트 깜빡임이 아니라 플레이어 본체의 외곽선과 짧은 잔상으로 알린다.

### 5.3 감정 스킬

- 우상단에는 현재 지역에서 활성화된 감정 문양 하나만 표시한다.
- 스킬 이름은 첫 획득과 메뉴에서만 쓰고, 평소에는 문양과 현재 입력 아이콘을 사용한다.
- 쿨타임은 소수점 숫자 대신 문양 둘레가 다시 차는 원형 진행으로 표시한다.
- 마지막 0.5초에는 문양이 한 번 정렬되며 준비 완료음을 낸다.
- 사용 불가 사유는 다음처럼 대상 가까이에 1초 이내로 표시한다.

| 상황 | 피드백 |
| --- | --- |
| 대상 없음 | 문양이 반 바퀴 돌다 원위치 + 짧은 빈 소리 |
| 쿨타임 | 남은 원형 구간이 한 번 밝아짐 |
| 피격 취소 | 채널링 선이 끊어져 플레이어 쪽으로 되돌아감 |
| 숨죽이기 중 공격 | 공격 아이콘에 닫힌 눈꺼풀 표시 |
| 균열에서 자각 무력 | 자각 윤곽은 나타나지만 세계와 정렬되지 않음 |

### 5.4 되감기 채널링

되감기 게이지는 화면 우측 고정 위치가 아니라 **선택된 오브젝트 둘레**에 표시한다.

- 가장 가까운 유효 대상: 얇은 골드 외곽선.
- 입력 시작: 대상 주위 원호가 반시계 방향으로 찬다.
- 완료 70%: 입자와 음높이가 상승해 위험 중에도 남은 시간을 느끼게 한다.
- 완료: 원호가 닫히면서 오브젝트 쪽으로 흡수되고 대상이 복원된다.
- 대상이 여럿이면 선택된 대상만 강한 외곽선을 쓰고 나머지는 30% 밝기로 낮춘다.
- 화면 밖 대상은 자동 선택하지 않는다.

### 5.5 숨죽이기

- 별도 지속 게이지는 두지 않는다.
- 시작 시 HUD 감정 문양이 수축하고, 화면 가장자리의 대비가 약해지며 호흡 소리가 가까워진다.
- 시선에 안전하게 숨은 동안 플레이어 주위에 닫힌 눈꺼풀형 얇은 링을 표시한다.
- 해제할 공간이 부족하면 원래 크기로 복귀하지 않고 문양이 좌우로 흔들리며 “공간이 부족합니다”를 한 번만 표시한다. 이 동작은 코드 안전 처리와 함께 구현해야 한다.

### 5.6 예지

- 사용 순간 문양에서 예측 대상까지 얇은 선이 120ms만 나타나 자동 대상 선택을 설명한다.
- 미래 고스트는 흰색 외곽선, 35% 투명도, 짧은 잔향을 사용한다.
- 미래에 사라지는 오브젝트는 “고스트 없음”만으로 경고하지 않는다. 현재 오브젝트 외곽이 2회 끊어지는 소멸 표식을 추가한다.
- 예지 가능 대상이 없으면 카메라 전체 효과를 재생하지 않고 문양만 짧게 갈라졌다 합쳐진다.

### 5.7 자각

- 자각은 별도 능력 게이지가 아니라 플레이어 중심의 상태로 표현한다.
- 홀드 시작 250ms 동안 채도가 빠지고, 안정 요소는 단선, 반응 요소는 이중 윤곽으로 분리된다.
- 응시에서 해금되기 전에는 입력해도 UI 반응을 만들지 않는다. 존재 자체를 미리 스포일러하지 않는다.
- 균열에서는 UI와 화면 탈채도는 정상 작동하지만 반응 오브젝트가 없어야 한다. “고장” 문구는 표시하지 않는다.
- 엔딩에서는 HUD를 전부 감추고, 홀드 진행도도 숫자나 게이지로 보이지 않는다. 이상 현상의 강도만 단계적으로 올라간다.

### 5.8 보스 HUD

- 보스 조우가 확정되고 출구가 잠긴 뒤 하단 중앙에 나타난다.
- 이름은 첫 1.5초만 보이고 이후 얇은 체력선과 단계 마디만 남긴다.
- 단계 전환 지점을 미리 정확히 표시하지 않고, 이미 넘어간 단계 경계만 흔적으로 남긴다.
- 체력선은 피해 즉시 감소하는 현재 체력과 300ms 늦게 따라오는 잔상 체력을 함께 보여 타격감을 만든다.
- 일반 정예에는 보스 HUD를 사용하지 않는다.

## 6. 상황 피드백

### 6.1 토스트 우선순위와 큐

동시에 발생한 메시지는 다음 우선순위로 최대 3개까지 큐에 쌓는다.

1. 스킬·자각 획득
2. 체크포인트·숏컷·보스 보상
3. 파편 문장
4. 체력 조각·중요 아이템
5. 재화

앞 메시지를 취소하지 않고 중요도에 따라 표시한다. 같은 재화는 0.8초 동안 합산해 `+7`처럼 한 번만 보여준다.

### 6.2 획득 피드백

| 획득 | 위치 | 지속 | 입력 차단 |
| --- | --- | ---: | --- |
| 재화 | 좌하단 작은 토스트 | 1.5초 | 없음 |
| 파편 | 하단 중앙 두 줄 | 읽기 시간 자동 계산, 최소 4초 | 없음 |
| 체력 조각 | 화면 중앙 아래 | 2.5초 | 없음 |
| 스킬 | 캐릭터 중심 연출 후 화면 중앙 | 4~6초 | 최초 1.2초만 이동 잠금 |
| 자각 | 월드 연출 중심 | 연출 스토리보드 기준 | 의도된 짧은 잠금 |
| 숏컷 | 해당 장치 주변 + 작은 토스트 | 2초 | 없음 |

파편 표시 시간은 `max(4초, 글자 수 × 0.12초)`를 기본으로 하고 접근성 설정에서 0.8~2배로 조절한다.

### 6.3 저장 표시

- 체크포인트 활성화 직후 우하단에 작은 원이 한 바퀴 감기며 `기억하는 중`을 표시한다.
- 저장이 끝나면 원이 닫히고 1초 뒤 사라진다.
- 저장 실패 시 붉은 경고 대신 `저장하지 못했습니다. 다시 시도합니다.`를 유지 표시하고 자동 재시도한다.
- 저장 중 종료를 선택하면 저장 완료까지 기다리는 모달을 표시한다.

### 6.4 상호작용 프롬프트

- 상호작용 대상에서 1.5m 이내, 플레이어가 대상을 향할 때만 표시한다.
- `[키 아이콘] 행동` 형식이며 `E` 같은 실제 키를 문자열로 저장하지 않는다.
- 반복 가능한 행동은 매번 표시하지만, 이미 학습한 이동·공격 튜토리얼은 표시하지 않는다.
- 월드 프롬프트는 대상 위가 아니라 플레이어와 대상 사이의 빈 공간에 배치한다.

## 7. 튜토리얼과 온보딩

### 7.1 원칙

- 설명보다 안전한 행동 유도 → 성공 확인 → UI 축소 순서를 따른다.
- 한 번에 새 입력 하나만 소개한다.
- 플레이어가 이미 행동했다면 해당 튜토리얼을 건너뛴다.
- 실패가 입력 부족인지 규칙 오해인지 구분해 힌트를 다르게 준다.
- 튜토리얼은 일시정지 메뉴의 `조작법`에서 다시 볼 수 있다.

### 7.2 프롤로그 순서

| 단계 | 공간 설계 | 최초 표시 | 성공 조건 | 재힌트 |
| --- | --- | --- | --- | --- |
| 이동 | 평지와 오른쪽 빛 | 이동 스틱/방향키 | 3m 이동 | 8초 정지 |
| 점프 | 낮은 턱 | 점프 아이콘 | 턱 위 착지 | 2회 실패 |
| 공격 | 움직이지 않는 약한 잔재 | 공격 아이콘 | 1회 적중 | 적 근처 4초 |
| 대시 | 넓지만 안전한 틈 | 대시 아이콘 | 틈 건너기 | 2회 낙하 |
| 벽점프 | 짧은 굴뚝 | 방향+점프 애니메이션 | 꼭대기 도달 | 높이 진전 없음 6초 |

달리기는 필수 진입을 막지 않으므로 별도 팝업 대신 이동 힌트의 보조 입력으로만 보여준다.

### 7.3 감정 능력 학습

각 능력은 동일한 세 단계로 가르친다.

1. **관찰:** 안전한 방에서 대상이 먼저 자신의 규칙을 보여준다.
2. **행동:** 입력 아이콘과 한 문장만 표시한다.
3. **전이:** 2분 안에 이동 또는 전투와 결합된 상황을 제공한다.

문구 예시는 다음처럼 짧게 유지한다.

- 되감기: `붙잡고 있으면, 무너지기 전으로 돌아갑니다.`
- 숨죽이기: `작아지면 시선이 지나칩니다.`
- 예지: `다가올 자리를 먼저 봅니다.`
- 자각: `피하지 말고, 그대로 바라봅니다.`

### 7.4 적응형 힌트

- 같은 장애물에서 3회 사망: 조작법이 아니라 위험의 예고 신호를 강조한다.
- 90초 이상 방 안에 머무르고 출구 접근이 없음: 카메라가 랜드마크 방향으로 0.5초 미세 이동한다.
- 스킬 획득 후 2분 동안 사용 없음: 우상단 문양에 입력 아이콘을 한 번 다시 표시한다.
- 힌트 강도는 `없음 / 최소 / 기본`으로 설정할 수 있다.

## 8. 지도와 길 찾기

### 8.1 역할

지도는 정답 경로를 알려주는 내비게이션이 아니라, 플레이어가 이미 경험한 공간을 정리하는 기억 도구다.

- 방문한 방만 윤곽 표시.
- 현재 방은 호흡하는 원으로 표시.
- 확인한 출구는 선, 통과하지 않은 출구는 끊어진 선.
- 체크포인트·열린 숏컷·보스방·지역 출구만 기본 아이콘으로 제공.
- 비밀방과 파편은 발견 후에만 표시.
- 미수집 파편 총량이나 비밀방 개수는 표시하지 않는다.
- 목적지 화살표와 자동 경로선은 기본 제공하지 않는다.

### 8.2 지도 화면

```text
┌──────────────────────────────────────────────────────────┐
│  지도       기억 기록       조작법       설정            │
├───────────────┬──────────────────────────────────────────┤
│ 잔재          │           ┌R08──R09──R10                 │
│ 응시          │     R05──R06──R07  ╲                     │
│ 균열          │  R01──R02──R03──R04  R11──R12            │
│               │          ○ 현재                          │
├───────────────┴──────────────────────────────────────────┤
│ [확대] [축소] [지역 전환]             최근 체크포인트    │
└──────────────────────────────────────────────────────────┘
```

- 방의 실제 기하를 축소 복제하지 않고 연결 관계 중심의 노드 지도를 사용한다.
- 지역별 색은 배경이 아니라 얇은 외곽에만 써 밝은 균열에서도 읽히게 한다.
- 지도 오픈 시 게임은 일시정지한다.
- 지도에서 빠져나오면 일시정지 메뉴가 아니라 곧바로 게임으로 돌아가는 단축 입력을 지원한다.

### 8.3 세계 안 길 찾기 우선순위

1. 원경 랜드마크와 공간 실루엣.
2. 실제 발판의 공통 명도선.
3. 바람·먼지·시선·예지 잔향 같은 방향성 움직임.
4. 열리지 않은 문과 능력 문양.
5. 메뉴 지도.

지도 없이도 주 동선을 찾을 수 있어야 하며, 지도는 이미 본 경로를 기억하는 데만 필요해야 한다.

## 9. 기억 기록

### 9.1 구조

파편은 번호 목록보다 의미의 연결을 보여준다.

```text
기억 기록
├─ 과거의 흔적       잔재에서 얻은 파편
├─ 타인의 시선       응시에서 얻은 파편
├─ 오지 않은 장면    균열에서 얻은 파편
└─ 겹쳐진 기억       두 개 이상 연결 조건을 충족한 해석
```

- 수집 순서로 먼저 보여주고 지역 필터를 제공한다.
- 항목에는 실제 문장, 발견 장소의 작은 실루엣, 연결된 파편만 표시한다.
- 아직 얻지 않은 파편은 빈 슬롯으로 표시하지 않는다.
- 새 연결이 생기면 `새 기록` 점 하나만 표시하고 강제 팝업을 띄우지 않는다.
- 엔딩에 필요한 최종 기억만 진행 조건이 충족되면 별도 원형 자리를 만든다.

### 9.2 연속 파편 처리

- 파편을 연속 획득해도 화면 표시는 큐로 보존한다.
- 일시정지 메뉴를 열면 현재 표시 중인 파편의 남은 시간이 정지한다.
- 표시를 놓친 경우 기록 메뉴의 가장 위에 `최근` 배지를 붙인다.

## 10. 메뉴와 주요 흐름

### 10.1 타이틀

버튼 순서는 다음으로 고정한다.

1. 이어하기 — 저장이 없으면 숨김.
2. 새 게임.
3. 설정.
4. 제작진.
5. 종료 — 콘솔 빌드에서는 숨김.

`잔재 지역 (작업 중)` 버튼은 개발 빌드에서만 표시한다.

기존 저장이 있을 때 새 게임을 선택하면 다음 확인을 사용한다.

> 새로운 꿈을 시작하면 현재 기억을 덮어씁니다.
> `[취소] [새 게임 시작]`

파괴적 선택은 기본 포커스를 항상 `취소`에 둔다.

### 10.2 일시정지

```text
┌──────────────────────────────────────────────┐
│ 일시정지                                    │
│                                              │
│  계속하기                                    │
│  지도                                        │
│  기억 기록                                   │
│  조작법                                      │
│  설정                                        │
│  체크포인트로 돌아가기                       │
│  타이틀로                                    │
│                                              │
│ 현재 지역 · 최근 저장 00:12 전               │
└──────────────────────────────────────────────┘
```

- 열릴 때 현재 선택은 `계속하기`.
- 같은 일시정지 버튼으로 어느 하위 탭에서도 즉시 게임 복귀.
- `체크포인트로 돌아가기`는 사망과 같은 월드 초기화 규칙을 적용한다는 확인을 표시한다.
- `타이틀로`는 진행도를 초기화하지 않는다. 저장 후 타이틀로 이동한다.
- 저장이 구현되기 전까지는 `타이틀로 이동하면 현재 세션이 사라집니다` 확인이 반드시 필요하다.

### 10.3 사망과 재도전

```text
피격 → 0.25초 충격 정지 → 0.7초 캐릭터 소멸
     → 0.5초 암전 → 체크포인트 상태 복원
     → 0.5초 페이드인 → 1초 안전 시간 → 조작
```

- `YOU DIED` 같은 큰 문구보다 화면 중앙의 작은 `다시 기억합니다`를 0.8초 표시한다.
- 보스 사망 시 최근 체크포인트가 보스 바로 전이면 추가 메뉴 없이 자동 재도전한다.
- 같은 보스에서 5회 실패하면 `전투 힌트 보기`를 사망 화면 하단에 선택적으로 제공한다.
- 낙사와 전투 사망의 월드 초기화 규칙은 같게 유지하되, 낙사는 더 짧은 전환을 사용한다.

### 10.4 씬 전환과 로딩

- 0.5초보다 긴 로딩이 예상되면 암전 중 지역 문양을 표시한다.
- 로딩 중 입력은 모두 차단하고 완료 후 한 프레임 뒤 복구한다.
- 첫 지역 진입 때만 지역명을 2초간 표시하고 재방문에서는 생략한다.
- 지역명 아래 감정명은 직접 쓰지 않는다. `잔재`, `응시`, `균열`만 보여준다.

## 11. 설정과 접근성

### 11.1 게임플레이

- 힌트 강도: 없음 / 최소 / 기본.
- 카메라 흔들림: 0~100%, 기본 60%.
- 히트스톱: 켬/끔.
- 자동 일시정지: 포커스 상실 시 켬.
- 보스 재도전 힌트: 켬/끔.

### 11.2 조작

- 이동, 점프, 대시, 공격, 감정 스킬, 자각, 지도, 일시정지를 모두 리맵 가능하게 한다.
- 키보드·마우스와 게임패드 바인딩을 별도로 저장한다.
- 같은 장치 내 충돌 바인딩을 즉시 표시한다.
- 홀드 동작은 `홀드 / 토글` 선택을 제공한다. 숨죽이기와 자각에 적용하되 되감기는 채널링 의미 때문에 홀드를 유지한다.
- 현재 사용 장치를 마지막 유효 입력으로 판정하고 모든 프롬프트를 150ms 안에 교체한다.

### 11.3 오디오

- Master, BGM, Ambience, SFX, UI를 0~100으로 분리.
- 백그라운드 음소거.
- 모노 오디오.
- 시선 접근음, 보스 예고음 같은 핵심 신호는 SFX 그룹에 포함하고 완전히 음소거했을 때 시각 신호를 강화한다.

### 11.4 화면

- 창 모드, 해상도, 수직 동기화, 프레임 제한.
- 밝기 조절 화면은 잔재의 어두운 실루엣과 균열의 밝은 윤곽을 동시에 보여준다.
- 화면 플래시: 0~100%.
- 자각 탈채도: 30~100%. 0까지 낮추지 않아 능력 상태를 완전히 잃지 않게 한다.

### 11.5 접근성

- UI 크기 100/125/150%.
- 파편 표시 시간 0.8/1/1.5/2배, 직접 넘기기 모드.
- 색각 보조 프리셋과 각 감정 문양의 형태 강조.
- 위험 윤곽 강화.
- 배경 대비 낮추기.
- 화면 흔들림·모션 블러·색수차·플래시 개별 감소.
- 반복 입력 완화와 홀드 임계시간 0.3~1.5초 조절.
- 모든 중요한 효과음에 방향성 화면 가장자리 표시를 선택적으로 제공.

## 12. UX 카피 규칙

### 12.1 문체

- 세계·감정 관련 문구는 짧고 현재형으로 쓴다.
- 시스템 오류와 저장 문구는 시적 표현보다 명확성을 우선한다.
- 명령형보다 행동 결과를 설명한다.
- 버튼은 명사보다 동사로 쓴다: `계속하기`, `돌아가기`, `새 게임 시작`.

### 12.2 예시

| 상황 | 권장 문구 | 피할 문구 |
| --- | --- | --- |
| 저장 완료 | `기억했습니다.` | `SAVE COMPLETE` |
| 저장 실패 | `저장하지 못했습니다. 다시 시도합니다.` | `Error 104` |
| 대상 없음 | 문구 없이 빈 피드백 | `사용할 수 없습니다!` |
| 체크포인트 복귀 | `최근 기억으로 돌아갈까요?` | `진행 상황을 리셋할까요?` |
| 새 게임 덮어쓰기 | `현재 기억을 덮어씁니다.` | `세이브 데이터 삭제` |
| 자각 해금 | `피하지 말고, 그대로 바라봅니다.` | `Awareness Unlocked!` |

오류 코드가 필요하면 상세 정보 화면이나 로그에만 제공한다.

## 13. Unity 구현 설계

### 13.1 기술 기준

- 런타임 `new GameObject()` 조립 방식에서 프리팹 기반 화면으로 전환한다.
- 텍스트는 TextMeshProUGUI로 통일하고 한글 SDF 폰트 에셋을 포함한다.
- 입력은 Unity Input System의 액션과 장치별 바인딩을 기준으로 한다.
- UI는 씬별 중복 배치보다 `UIRoot` 하나를 Bootstrap에서 유지하고 화면 상태를 전환한다.
- 월드 공간 프롬프트와 보스 전용 UI만 씬 오브젝트를 참조한다.
- 해상도 대응은 CanvasScaler와 SafeArea 컴포넌트에서 일괄 처리한다.

### 13.2 권장 구조

```text
UIRoot (DontDestroyOnLoad)
├─ ScreenLayer
│  ├─ TitleScreen
│  ├─ PauseScreen
│  ├─ MapScreen
│  ├─ JournalScreen
│  ├─ SettingsScreen
│  └─ ConfirmDialog
├─ HudLayer
│  ├─ PlayerStatusView
│  ├─ EmotionView
│  ├─ BossView
│  └─ SaveIndicator
├─ ToastLayer
│  ├─ NarrativeToast
│  └─ RewardToastQueue
├─ OverlayLayer
│  ├─ ScreenFader
│  └─ LoadingIndicator
└─ EventSystem
```

### 13.3 상태와 이벤트

UI가 매 프레임 게임 객체를 폴링하지 않도록 다음 이벤트를 제공한다.

| 이벤트 | 발행자 | 소비 UI |
| --- | --- | --- |
| HealthChanged | PlayerHealth | PlayerStatusView |
| EmotionChanged | EmotionSkillController | EmotionView |
| SkillCooldownChanged | EmotionSkill | EmotionView |
| SkillChannelChanged | RewindSkill | WorldChannelView |
| CurrencyChanged | ProgressState/서비스 | RewardToast, Journal |
| FragmentCollected | ProgressState/서비스 | NarrativeToast, Journal |
| CheckpointActivated | Checkpoint | SaveIndicator |
| SaveStateChanged | SaveService | SaveIndicator, 메뉴 |
| EncounterStarted/Ended | Encounter | BossView, 출입구 피드백 |
| InputDeviceChanged | InputService | 모든 프롬프트 |

쿨타임·채널링처럼 연속 값은 이벤트 시작/종료와 View의 제한된 업데이트를 조합한다. HUD 전체가 매 프레임 문자열을 다시 만드는 방식은 피한다.

### 13.4 데이터 자산

- `UIThemeData`: 색, 폰트, 간격, 모션 시간, 아이콘.
- `InputGlyphData`: 장치·바인딩별 아이콘.
- `TutorialData`: ID, 조건, 문구 키, 성공 조건, 재힌트 조건.
- `MapData`: 방 ID, 연결, 아이콘, 발견 조건.
- `LocalizationTable`: UI와 튜토리얼 문구.
- `AccessibilitySettings`: 모든 접근성 옵션의 저장 데이터.

### 13.5 현재 코드의 우선 수정

1. `PauseMenu.GoToTitle()`의 `Progress.ResetAll()` 제거와 확인/저장 흐름 추가.
2. `HUD`의 고정 `HeartCount = 3`을 동적 최대 체력 표시로 변경.
3. 파편 한 줄 교체를 토스트 큐와 기록 저장으로 변경.
4. 튜토리얼의 `K`, `L` 문자열을 Input Action 바인딩에서 생성.
5. 타이틀의 개발 버튼을 `DEVELOPMENT_BUILD` 조건으로 제한.
6. 스킬 쿨타임의 매 프레임 텍스트 생성 대신 아이콘·진행 링 적용.
7. `CanvasScaler`의 기준 해상도·Match 값을 모든 Canvas에서 통일.
8. 메뉴에 EventSystem 포커스와 게임패드 내비게이션 추가.

## 14. 제작 순서

### UI-0 — 안전한 메뉴 흐름

- 타이틀 정리, 개발 버튼 제한.
- 일시정지에서 진행도 초기화 제거.
- 확인 대화상자, 키보드·패드 포커스, CanvasScaler 통일.
- 저장 구현 전 임시 유실 경고.

완료 조건: 메뉴 입력 때문에 진행도가 의도치 않게 사라지지 않는다.

### UI-1 — 전투 HUD와 상황 피드백

- 동적 체력, 감정 문양, 쿨타임 링.
- 대상 주변 되감기 채널링.
- 피해·회복·사용 실패 피드백.
- 보스 HUD와 토스트 큐.

완료 조건: 플레이어가 텍스트 숫자를 읽지 않고도 생존·스킬 상태를 판단한다.

### UI-2 — 입력과 온보딩

- Input System·리맵·장치 자동 전환.
- 동적 입력 아이콘.
- 튜토리얼 데이터와 성공 조건.
- 조작법 메뉴, 적응형 힌트.

완료 조건: 키보드와 게임패드 신규 플레이어가 프롤로그를 막힘 없이 통과한다.

### UI-3 — 지도와 기억 기록

- 방 발견 상태와 노드 지도.
- 체크포인트·숏컷·현재 위치 표시.
- 파편 기록, 최근 항목, 연결된 기억.

완료 조건: 놓친 텍스트를 다시 읽고 이미 방문한 경로를 복원할 수 있다.

### UI-4 — 설정과 접근성

- 오디오·화면·게임플레이·접근성 설정.
- 저장 연동.
- 다양한 화면비·UI 배율·색각 보조 검증.

완료 조건: 설정이 즉시 미리 보이고 재실행 후 유지된다.

### UI-5 — 최종 아트와 모션

- 최종 폰트·아이콘·패널·감정별 문양.
- 메뉴 전환·토스트·체력·스킬 모션.
- UI SFX와 지역별 미세 톤 조정.

완료 조건: UI가 세 지역에서 같은 기능성과 게임 고유의 정체성을 모두 유지한다.

### 구현 현황 (2026-07-28)

| 루프 | 구현 상태 | 코드 기준 결과 |
|---|---|---|
| UI-0 | 구현 | 공통 Canvas 배율, 키보드·패드 포커스, 확인 대화상자, 체크포인트·타이틀 안전 흐름 |
| UI-1 | 구현 | 동적 최대 체력, 감정·쿨다운, 월드 채널링, 보스 체력, 순차 토스트와 진행 이벤트 |
| UI-2 | 구현 | 키보드·게임패드 자동 감지, 동적 튜토리얼 표기, 충돌 방지 키보드 리맵, 조작법 화면 |
| UI-3 | 구현 | 방문 방 기반 노드형 기억 지도, 수집 파편 원문 기록, `M` 지도 토글 |
| UI-4 | 구현 | 음량·UI 배율·메시지 시간·동작/섬광 감소·고대비 설정과 `PlayerPrefs` 지속 |

현재 프로젝트의 게임 입력은 레거시 `Input` API 위에 `InputPrompts` 바인딩 계층을 두었다. 장치 전환과 키보드 리맵은 동작하지만, Unity Input System 액션 에셋으로의 물리적 전환은 패키지 도입과 전체 플레이 회귀가 필요한 별도 마이그레이션 작업이다. 공개 API를 `InputPrompts`와 `PlayerInput`에 모아 UI를 다시 만들지 않고 내부 입력 공급자만 교체할 수 있게 했다.

최종 비주얼 제작 규격, 우선순위와 생성 프롬프트 참고안은 [UI_VISUAL_ASSET_LIST.md](./UI_VISUAL_ASSET_LIST.md)를 단일 목록으로 사용한다.

## 15. 테스트 체크리스트

### 기능

- [ ] 최대 체력 증가·회복·피해가 HUD에 정확히 반영된다.
- [ ] 스킬 획득·지역 전환·쿨타임·취소 상태가 일치한다.
- [ ] 파편을 연속 획득해도 문장이 유실되지 않는다.
- [ ] 일시정지 중 게임 시간은 멈추고 UI 모션은 동작한다.
- [ ] 타이틀 이동과 새 게임 확인에서 진행도가 의도대로 유지·초기화된다.
- [ ] 저장 중 종료와 저장 실패가 안전하게 처리된다.

### 입력

- [ ] 모든 화면을 키보드, 게임패드, 마우스로 각각 완주할 수 있다.
- [ ] 장치를 바꾸면 프롬프트가 즉시 갱신된다.
- [ ] 리맵 충돌과 필수 액션 미지정이 방지된다.
- [ ] 메뉴를 닫았을 때 게임 입력이 같은 프레임에 발동하지 않는다.

### 화면과 접근성

- [ ] 1280×720, 1920×1080, 2560×1440, 21:9에서 잘리지 않는다.
- [ ] UI 150%에서도 핵심 메뉴가 겹치지 않는다.
- [ ] 색을 제거해도 모든 감정·위험 신호를 구분한다.
- [ ] 화면 흔들림·플래시 0에서도 피드백 의미가 유지된다.
- [ ] 최소 글자 크기와 대비 기준을 만족한다.

### 플레이테스트 질문

- 지금 체력이 얼마 남았는가?
- 감정 스킬을 지금 사용할 수 있는가? 없다면 왜인가?
- 방금 무엇을 얻었는가?
- 어디로 가야 한다고 생각하는가? 어떤 단서 때문인가?
- 사망 후 무엇이 유지되고 무엇이 초기화됐는가?
- 마지막으로 읽은 파편을 다시 찾을 수 있는가?

플레이어가 화면을 가리키지 않고도 이 질문에 답할 수 있으면 정보 구조가 제대로 작동한 것이다.
